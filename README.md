# Семейный образовательный портал

**Живой сайт: https://cheremisin.github.io/jbqye7itb8dg/**

Семейный портал подготовки к поступлению в ведущие вузы России. Статический сайт, работает на GitHub Pages, без бэкенда. Прогресс, заметки и результаты тестов хранятся в браузере (localStorage) с экспортом и импортом JSON.

Данные исследования собраны **9 августа 2026 года**.

## Как выложить на GitHub Pages

### Вариант A — через веб-интерфейс, без установки чего-либо

1. Зайдите на [github.com/new](https://github.com/new), создайте репозиторий со случайным именем (так адрес сайта нельзя будет угадать). Для бесплатного GitHub Pages репозиторий должен быть публичным.
2. На странице репозитория нажмите **Add file → Upload files**, перетащите туда **всё содержимое** этой папки (включая папки `assets` и `data`, и файл `.nojekyll`).
3. Нажмите **Commit changes**.
4. Перейдите в **Settings → Pages**. В разделе *Build and deployment* выберите Source: **Deploy from a branch**, Branch: **main**, папка: **/ (root)**. Нажмите **Save**.
5. Через 1–2 минуты сайт будет доступен по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

> Файл `.nojekyll` нужен обязательно: без него GitHub Pages пытается обработать сайт через Jekyll и может игнорировать некоторые файлы.

### Вариант B — через командную строку

```bash
cd путь/к/этой/папке
git init
git add .
git commit -m "Образовательный портал: первая версия"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

Затем шаг 4 из варианта A.

### Локальный запуск

Просто откройте `index.html` двойным щелчком — сайт работает без сервера. Данные хранятся отдельно для локальной версии и для версии на GitHub Pages (браузер считает их разными сайтами), поэтому выберите что-то одно как основное.

## Как обновлять содержание

Всё содержание вынесено в папку `data/` — это обычные JavaScript-файлы, их можно править в любом текстовом редакторе.

| Файл | Что править |
|---|---|
| `data/deadlines.js` | Календарь дат. Поле `approx:true` означает «дата по прошлому сезону» и рисует звёздочку |
| `data/olympiads.js` | Каталог олимпиад |
| `data/resources.js` | Каталог ресурсов. `star:true` поднимает запись наверх и помечает ★ |
| `data/plans.js` | Планы детей: стратегия, задачи, недельный ритм, календарь года |
| `data/prompts.js` | Промпты для ИИ |
| `data/tests.js` | Утверждения тестов и описания типов |
| `data/tasks.js` | Недельные наборы заданий |
| `data/professions.js` | Каталог профессий, сокращающиеся занятия, группы навыков |
| `data/missions.js` | Нерешённые задачи, исследования о мотивации, ролевые модели, зарубежные программы, локальные возможности |
| `data/config.js` | **Имена детей.** Задаются по падежам в одном месте; в текстах стоят токены `{{U}}`, `{{Yg}}` и т.п. |

**Важно:** у задач в `plans.js` первый элемент — идентификатор (`'u-zftsh'`). Если его изменить, галочка «выполнено» для этой задачи потеряется. Добавлять новые задачи безопасно, менять id существующих — нет.

## Приватность: что сделано и чего это не даёт

Репозиторий публичный — иначе GitHub Pages не работает бесплатно. Чтобы сайт не был «виден везде», сделано три вещи:

1. **Неугадываемый адрес.** Репозиторий называется случайной строкой, поэтому URL сайта подобрать нельзя.
2. **Запрет индексации.** На всех страницах `<meta name="robots" content="noindex,nofollow">` плюс `robots.txt` — поисковики сайт в выдачу не поставят.
3. **Нейтральные имена.** В `data/config.js` стоят «Дочь» и «Сын», а не настоящие имена. Чтобы видеть настоящие — впишите их по падежам в `data/config.js` **в локальной копии** на диске и не коммитьте этот файл. Подстановка на всех страницах произойдёт автоматически.

**Чего это не даёт.** Публичный репозиторий остаётся в списке репозиториев профиля GitHub, и любой, кто откроет профиль, увидит его и сможет зайти внутрь. Ссылка «скрыта» ровно в том смысле, что её нельзя угадать и найти поиском, — но она не защищена паролем. Ничего, что не должно попасть к посторонним, сюда класть не стоит.

Если понадобится настоящая закрытость: приватный репозиторий с GitHub Pro (около $4 в месяц) либо перенос сайта на Cloudflare Pages со случайным поддоменом и входом по коду на почту (бесплатно, но нужен аккаунт Cloudflare).

Прогресс, заметки и результаты тестов в репозиторий не попадают вообще — они живут только в браузере.

## Резервное копирование

Прогресс живёт только в браузере. Если почистить историю или сменить устройство — данные пропадут.

Раз в месяц: **Дашборд → Скачать копию (JSON)**, и положить файл в папку проекта на Яндекс.Диске. Восстановление — кнопка «Загрузить копию» там же.

## Как обновить опубликованную версию

Через веб-интерфейс: **Add file → Upload files**. Важно: для файлов из вложенных папок открывайте адрес вида `.../upload/main/data` или `.../upload/main/assets/js`, иначе структура папок потеряется и сайт сломается.
